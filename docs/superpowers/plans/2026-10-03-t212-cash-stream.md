# T212 Cash-Transaction Stream Implementation Plan

**Status (2026-10-03):** In progress. Encoding record signed off:
`docs/research/t212-cash-transaction-encoding.md` (read it first; it is the
binding spec). Parent: `2026-09-20-t212-snapshot-first-sync.md` §5.5 items 7-8.

**Goal:** import `/equity/history/transactions` as a third sync stream `cash`
so deposits, withdrawals, fees and interest reach the ledger and the cash
reconciliation can agree with the broker.

**Architecture:** `cash` is added to `t212_sync.STREAMS` and flows through the
existing machinery (staging, per-page checkpoints, rate limits, incremental stop
rule, audits, finalization). A pure mapper `t212_cash.py` turns one staged event
into a ledger row or an "unsupported" verdict; unsupported events send the run to
`needs_review`.

## Global constraints

- Every row is `source="t212_api"`, `source_event_stream="cash"`,
  `source_event_id="cash:<reference>"`, `ticker=None`, `shares=0`, `price=0`,
  `amount=|amount|`, `currency=event currency`, `executed_at=dateTime`,
  `date=UTC date`. Direction comes from the ledger type, never from a signed amount.
- Mapping (record, Decision): `DEPOSIT`->deposit, `WITHDRAW`->withdrawal,
  `FEE`->fee, `INTEREST_ON_FREE_CASH`/`LENDING_INTEREST`->interest,
  `TRANSFER` by sign (>0 deposit, <0 withdrawal; notes keep "TRANSFER").
  Zero/non-numeric amount, empty currency, any other type -> unsupported.
- Fail closed: an unsupported event sends the run to `needs_review` before any
  ledger write; cash history is not marked complete.
- `EXPECTED_ALEMBIC_HEAD` must equal the new single head in the same change.
- Run the fast suite from `backend/` with `.venv/Scripts/python -m pytest tests/
  --ignore=tests/postgres -q`; RED first for every behavior change.
